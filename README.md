# 婚礼请柬 H5

一个移动端优先的婚礼请柬网页，为微信分享场景设计。

- **无框架、无构建、无外部依赖**：纯 HTML/CSS/JS，可直接托管在任何静态空间
- **无外部字体**：全部使用系统字体，国内访问不会被 Google Fonts 拖住
- **7 屏叙事**：封面 → 邀请函 → 开篇·中式 → 日常·生活 → 此时·浪漫 → 回归·平凡 → 敬候光临

## 目录结构

```
index.html              页面本体（改文字就改这个文件）
assets/css/style.css    样式
assets/js/main.js       交互：启幕、灯箱、音乐、复制地址
assets/audio/bgm.mp3    背景音乐（需自备，见下文）
img/lg/                 长边 1600 的展示图（JPG + WebP）
img/sm/                 长边 720 的缩略图
img/share.jpg           800×800 微信分享缩略图
img/lqip.json           模糊占位图数据
photo/                  原图存档，292 MB，网页不直接引用
tools/build_images.py   原图 → 网页图（可重复执行）
tools/build_page.py     生成 index.html（会覆盖手改内容，慎用）
tools/build_preview.py  打包成单文件预览版（CSS/JS/图片全部内联）
```

## 要改的地方

打开 `index.html`，搜索 `【改这里】`，一共两处：

| 位置 | 内容 |
| --- | --- |
| 第 1 屏 封面 | 抬头、新郎/新娘姓名、日期、场地 |
| 第 2 屏 邀请函 | 邀请文案、公历农历、场地、开礼/开席/喜门、导航链接 |

原先独立的「婚礼信息」一屏已并入第 2 屏 —— 日期、农历、星期、开礼、开席、喜门、
场地在两屏之间完全重复，真正独有的只有底部的「地图导航」「复制地址」两个按钮。

另外在 `<head>` 里改两处分享信息：`<title>`、`<meta name="description">` 和 `og:` 系列。

姓名、日期、场地、开礼/开席/喜门时间均已填入真实信息，没有遗留占位内容。

详细地址就是酒店名本身，与页面上方的场地完全重复，因此不单独显示一行——
`tools/build_page.py` 里的 `address` 留空即不渲染，日后若拿到具体街道门牌，
填进去就会自动显示出来。

### 导航链接怎么填

`地图导航` 按钮目前用的是**关键词搜索**（搜「朔州艺龙万国酒店」），
而不是写死经纬度 —— 编造的坐标会把宾客导到错误位置，比留占位更危险。

想要精确落点：

1. 打开 <https://lbs.amap.com/tools/picker> 搜索场地，复制经纬度
2. 把链接换成 `https://uri.amap.com/marker?position=经度,纬度&name=场地名称`

注意顺序是**经度在前、纬度在后**，和百度地图相反。

## 背景音乐

把音频文件放到 `assets/audio/bgm.mp3` 即可，页面会自动接上。
**文件不存在时音乐按钮会自动隐藏**，不会出现点了没反应的情况。

播放策略：

- **微信内**：监听 `WeixinJSBridgeReady` 事件自动播放（微信内置浏览器特有的口子）
- **其它浏览器**：iOS/Android 一律禁止自动播放，退化为「首次触屏时播放」
- 右上角唱片按钮随时可开关

建议控制在 3 MB 以内（约 3 分钟 128kbps），太大在移动网络下会拖慢首屏。
请使用你有权使用的音乐——商用流行歌曲放在公开网页上存在版权风险。

## 换照片

```bash
python3 tools/build_images.py    # 重新压缩 photo/ 里的原图
```

改分组、换封面则编辑 `tools/build_page.py` 顶部的 `CHAPTERS`，然后：

```bash
python3 tools/build_page.py      # ⚠️ 会整体覆盖 index.html
```

如果你已经手改过 `index.html` 的文字，跑这个会丢失，记得先备份。

## 本地预览

```bash
python3 -m http.server 8000
# 浏览器打开 http://localhost:8000
```

用手机预览：确保手机和电脑在同一 WiFi，访问 `http://电脑IP:8000`。

## 打包成单文件

```bash
python3 tools/build_preview.py
```

把 CSS、JS 和全部照片内联成一个约 4 MB 的自包含 HTML，不依赖任何外部资源，
可以直接发给别人或丢到任意静态空间预览。预览版不含音乐按钮（因为没有随附音频文件）。

# 关于微信分享（重点）

## 分享卡片有两种，能力差别很大

### 一、默认抓取卡片（当前方案，零配置）

把链接发到微信聊天，微信爬虫会自己抓取页面生成卡片：

- **标题** ← `<title>`
- **描述** ← `<meta name="description">`
- **缩略图** ← 微信自行从页面挑选，通常参考 `og:image` 和页面靠前的图片

本项目已经做了能做的全部优化：`og:image` 指向 800×800 的方图（微信要求 ≥300×300），
且封面照片是页面里第一个真实 `<img>`。

**但缩略图最终显示什么，决定权在微信，不保证。** 常见现象：

- 首次分享抓不到图，隔几小时或换个链接（加 `?v=2`）才正常
- 分享到「朋友圈」和「聊天」的表现不一致
- 微信有缓存，改了 meta 后旧卡片可能持续显示很久

### 二、完全自定义卡片（需要资质）

想要标题、描述、缩略图**完全可控**，必须接入微信 JS-SDK，前提条件：

1. **已认证的微信公众号**（服务号或订阅号，认证年费 300 元）
2. **已 ICP 备案的域名**，并在公众号后台配置为「JS 接口安全域名」
3. 后端提供签名接口（`wx.config` 需要 `signature`，签名必须在服务器算，
   `appsecret` 绝不能放前端）

满足后调用 `wx.updateAppMessageShareData()` / `wx.updateTimelineShareData()`。

**这是腾讯的平台规则，没有技术绕过办法。** 如果只是发给亲友，方案一通常够用。

## 托管：这是国内访问的关键

你说宾客主要在中国大陆，这里必须提醒：

### GitHub Pages 在国内不可靠

`github.io` 在大陆访问经常超时或极慢，微信内置浏览器可能直接白屏，
微信爬虫也可能抓不到页面导致卡片出不来。

**GitHub Pages 适合先做出来自己验证效果，不适合正式发给国内宾客。**

启用方式：仓库 Settings → Pages → Source 选 `Deploy from a branch` → `main` / `/ (root)`，
几分钟后访问 `https://aotaiyi.github.io/wedding/`。

### 正式发布建议迁到国内

本项目是纯静态站，迁移只是「把文件传上去」，没有任何改造成本：

| 方案 | 说明 |
| --- | --- |
| 阿里云 OSS / 腾讯云 COS + CDN | 最常见，几块钱/月，需要**已备案域名** |
| 各类国内静态托管 | 同样需要备案域名才能绑定 |

**备案是硬门槛**：需要中国大陆的域名、身份证、以及国内服务器/OSS，
个人备案通常 1–3 周。如果时间来不及，退而求其次的办法是把请柬做成图片或小程序。

迁移后记得同步修改 `index.html` 里 `og:image` 和 `og:url` 的绝对地址。

## 其它微信注意事项

- **下载类操作在微信内基本不可用**，所以本页没有做「添加到日历」的 .ics 下载，
  改用「复制地址」（微信内可用）+ 「地图导航」跳转
- 微信可能在页面顶部显示「非微信官方网页，请注意信息安全」提示条，这是正常的
- 微信有页面缓存，更新后如果没变化，可以在链接后加 `?v=2` 强制刷新

# 隐私提醒

**这个仓库目前是 Public（公开）的**，意味着 292 MB 的婚纱原图对全网公开、
可被任意下载和搜索引擎抓取。

如果不希望如此，去 Settings → 最下方 Danger Zone → Change visibility 改为 Private。
注意：**改为 Private 后 GitHub Pages 在免费账户下会不可用**（需要 Pro）。

如果打算用 GitHub Pages，一个折中做法是：仓库保持公开，但把 `photo/` 原图移出仓库
（本地或私有网盘存档），只保留 `img/` 里的压缩版。
